# AGENTS.md — правила работы AI с библиотекой иконок

Этот репозиторий содержит локальную библиотеку из **100 000 SVG-иконок**. Для любого UI/UX-задания агент должен сначала использовать эту библиотеку и только затем искать внешние ассеты.

## 1. Где лежат иконки

- `library/<prefix>/*.svg` — сами SVG, сгруппированные по исходным коллекциям.
- `manifest.jsonl` — полный индекс: `id`, имя, коллекция, категория, автор, лицензия и путь к SVG.
- `collections-selected.json` — метаданные выбранных коллекций.
- `ICON_LIBRARY_STATS.md` — количество и состав библиотеки.
- `THIRD_PARTY_LICENSES.md` — сведения об авторах и лицензиях.

Не сканируй все 100 000 SVG по содержимому без необходимости. Сначала ищи по `manifest.jsonl` и именам файлов.

## 2. Порядок выбора

1. Определи семантику: `search`, `settings`, `download`, `calendar`, `security`, `game`, `user`, `mail` и т.д.
2. Найди кандидатов в `manifest.jsonl` по английскому semantic name и близким синонимам.
3. Определи визуальный язык текущего экрана: outline / filled / rounded / color / emoji / brand / game.
4. Выбери одну основную коллекцию для одного визуального уровня интерфейса.
5. Открой 2–5 SVG-кандидатов и выбери наиболее понятный и визуально совместимый.
6. Только если подходящего результата нет среди 100 000 локальных иконок, допускается внешний поиск.

## 3. Рекомендуемые коллекции

- `tabler` — универсальный чистый outline UI.
- `ph` — Phosphor, современный UI с большим количеством вариантов.
- `fluent` — интерфейсы в духе Microsoft/Fluent.
- `material-symbols` — Material UI и универсальные системные действия.
- `material-symbols-light` — более лёгкий Material outline.
- `mdi` — очень широкое покрытие обычных UI-сценариев.
- `hugeicons` — современный выразительный UI.
- `iconmind` — широкая универсальная библиотека.
- `solar` — современный rounded/duotone визуальный язык.
- `game-icons` — игры, предметы, оружие, способности, RPG и игровые действия.
- `simple-icons` — логотипы брендов и сервисов.
- `token-branded` — Web3/crypto бренды.
- `openmoji`, `twemoji`, `noto` — цветные emoji/illustrative элементы; не использовать как случайную замену системным UI-иконкам.
- `thesvg-color` — цветные декоративные/feature assets.
- `arcticons` — большой набор app/system glyphs.

## 4. Консистентность важнее количества

Наличие 100 000 иконок не означает, что нужно смешивать коллекции.

- Для navbar/sidebar/toolbar старайся использовать одну коллекцию.
- Не смешивай outline, filled, emoji и цветные иллюстрации в одной группе controls.
- Второй стиль допустим для крупных feature/empty-state/decorative элементов.
- Сохраняй aspect ratio SVG.
- Не меняй stroke-width вручную без веской причины.
- Не растягивай SVG по одной оси.

## 5. Семантика

Смысл важнее визуальной красоты.

- Ищи точное действие, затем синонимы.
- Не используй визуально похожую, но семантически неверную иконку.
- Не оставляй icon-only action без accessible name, если смысл не очевиден.
- Destructive actions должны использовать однозначный символ.

Примеры поисковых терминов:

- удалить: `delete`, `trash`, `remove`;
- настройки: `settings`, `gear`, `cog`;
- аккаунт: `user`, `person`, `profile`, `account`;
- безопасность: `shield`, `lock`, `security`, `key`;
- загрузка: `download`, `save`, `arrow-down`;
- отправка: `send`, `paper-plane`, `arrow-up`;
- редактирование: `edit`, `pencil`, `pen`.

## 6. Размеры

- 16 px — dense desktop UI.
- 18–20 px — secondary actions.
- 24 px — default action/navigation.
- 32–48 px — cards/features.
- 64–128 px — empty states, onboarding и decorative icons.

Сравнивай optical weight соседних иконок, а не только их номинальный размер.

## 7. Цвет

- Для монохромных SVG предпочтительно наследование цвета через UI-токены, если структура SVG это поддерживает.
- Не ломай исходную палитру цветных/emoji наборов.
- Проверяй light/dark theme и контраст.
- Не вводи новый цвет только потому, что он присутствует в выбранной иконке.

## 8. Accessibility

- Decorative icon: `aria-hidden="true"`.
- Icon-only button: обязательный `aria-label`/accessible name.
- Не передавай критический статус только цветом.
- Для touch UI делай интерактивную область существенно больше самой пиктограммы, обычно около 40–44 px.

## 9. Использование в Web/React

Простой вариант:

```tsx
<button className="iconButton" aria-label="Открыть настройки">
  <img src="/icons/settings.svg" alt="" aria-hidden="true" width={24} height={24} />
</button>
```

Если пайплайн поддерживает SVG как компонент:

```tsx
<button aria-label="Поиск">
  <SearchIcon aria-hidden="true" focusable="false" />
</button>
```

Не копируй огромный inline SVG прямо в JSX без причины.

## 10. Поиск для AI-агента

Предпочтительный алгоритм:

```bash
# точное или частичное имя
rg -i '"name":"[^"]*(search|magnify)[^"]*"' manifest.jsonl

# конкретная коллекция + термин
rg -i '"prefix":"tabler".*"name":"[^"]*settings' manifest.jsonl

# поиск файлов
find library/tabler -iname '*search*.svg' | head -20
```

Если `rg` недоступен, используй `grep -i`.

Не загружай в контекст десятки тысяч строк manifest. Сначала сузь запрос до небольшой группы кандидатов.

## 11. Лицензии

Библиотека собрана из открытых коллекций Iconify, но разные наборы используют разные лицензии: MIT, Apache-2.0, CC0, CC BY, CC BY-SA и другие.

- Перед публичным распространением/релизом проверь метаданные соответствующей коллекции.
- Для наборов с attribution сохрани требуемую атрибуцию.
- Не удаляй `THIRD_PARTY_LICENSES.md`.
- Не утверждай, что все 100 000 иконок принадлежат этому репозиторию или имеют одну и ту же лицензию.

## 12. Анти-паттерны

Запрещено без веской причины:

- emoji вместо обычного UI icon;
- случайные Unicode-символы вместо имеющейся SVG;
- 3+ визуально разных icon styles в одной toolbar/navigation группе;
- разная оптическая масса соседних иконок;
- бессмысленное изменение оригинальной геометрии SVG;
- внешний поиск до проверки локальной библиотеки;
- генерация новой иконки, если в локальной библиотеке уже есть качественный подходящий вариант.

## 13. Главное правило

**Сначала `manifest.jsonl` → затем локальный SVG → затем проверка визуальной консистентности → только после этого внешний источник.**
