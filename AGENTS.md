# AGENTS.md — правила работы AI с иконками

Эти правила обязательны для любого AI-агента, который меняет UI/UX проекта.

## 1. Базовый принцип

Не вставляй случайные иконки и не смешивай визуальные языки. Для одного экрана выбирай один основной icon style. Второй стиль допускается только как акцент для крупных декоративных/feature-элементов.

## 2. Приоритет выбора стиля

1. **Claude Hand Drawn** — default для дружелюбных современных интерфейсов, SaaS, лендингов, onboarding, карточек, empty states.
2. **Liquid Glass** — только когда UI уже использует glassmorphism/translucency или нужен дорогой визуальный акцент.
3. **Tiny Color** — для плотных панелей, компактных controls, небольших экранов и мест, где важна читаемость.
4. **Dotted** — для больших размеров, лендингов, editorial/marketing и декоративных блоков.
5. **Puffy Outline** — для игровых/playful интерфейсов, не использовать в строгом enterprise UI без причины.
6. **3D Fluency** — для крупных feature icons, промо, empty-state, onboarding; не ставить в обычную navbar/sidebar.

## 3. Семантика важнее красоты

- Сначала ищи иконку по точному действию: `download`, `upload`, `settings`, `search`, `delete`, `filter`, `calendar`, `user`.
- Не заменяй точный смысл визуально похожим символом.
- Не используй иконку без подписи, если действие может быть неоднозначным.
- Для destructive action выбирай однозначный symbol и подтверждение в UX.

## 4. Консистентность

- Один набор stroke/fill на одном уровне UI.
- Не смешивай outline + 3D + glass в одной панели навигации.
- Не меняй толщину линий SVG вручную, если это ломает стиль набора.
- Сохраняй исходный aspect ratio.
- Для одного класса элементов используй одинаковый optical size.

## 5. Размеры

Рекомендуемая сетка:

- 16 px — очень плотный desktop UI, только хорошо читаемые icons.
- 18–20 px — secondary actions.
- 24 px — default navigation/action size.
- 32–48 px — cards/features.
- 64–128 px — empty states, promo, onboarding.

Claude Hand Drawn и Dotted часто лучше выглядят, когда им дают больше воздуха. 3D Fluency не уменьшай до размера мелкой toolbar-иконки.

## 6. Цвет

- Не перекрашивай многоцветные стили без необходимости.
- `currentColor` применяй только к SVG, который действительно рассчитан на одноцветное отображение.
- Цвет должен подчиняться design tokens проекта, а не вводить новый palette сам по себе.
- Проверяй контраст на light и dark background.

## 7. Accessibility

- Декоративная иконка: `aria-hidden="true"`.
- Единственный контент кнопки — иконка: обязательно `aria-label`/accessible name.
- Не передавай критический статус только цветом.
- Интерактивная зона должна быть больше самой пиктограммы; ориентир — около 40–44 px для touch target.

## 8. React / Web

Предпочтительный паттерн:

```tsx
<button className="iconButton" aria-label="Открыть настройки">
  <img src={settingsIcon} alt="" aria-hidden="true" width={24} height={24} />
</button>
```

Если SVG импортирован как компонент и лицензия/пайплайн это допускают:

```tsx
<button aria-label="Поиск">
  <SearchIcon aria-hidden="true" focusable="false" />
</button>
```

Не вставляй огромный inline SVG в JSX без необходимости.

## 9. Naming

В коде называй файл/компонент по **назначению**, а не по внешнему виду:

- хорошо: `search`, `calendar`, `security`, `download`;
- плохо: `roundThing`, `prettyIcon`, `icon2`.

Если есть варианты:

`search--claude-hand-drawn.svg`
`search--tiny-color.svg`

## 10. Лицензия и хранение

- Не коммить в этот репозиторий скачанные SVG/PNG Icons8 как самостоятельный asset pack.
- Проверяй актуальные условия Icons8 перед использованием.
- Free usage обычно требует attribution/link to Icons8.
- Для API используй официальный ключ и официальный API; не обходи лимиты и не scrape сайт.
- Не публикуй API key в Git.
- Локальные файлы, полученные пользователем на законных условиях, держи в `vendor/icons8/` или другом игнорируемом каталоге.

Официальные источники:
- https://icons8.com/license
- https://icons8.com/terms-and-conditions
- https://developers.icons8.com/docs/getting-started

## 11. Порядок действий агента

Перед изменением UI:

1. Определи роль иконки.
2. Посмотри существующий стиль экрана.
3. Выбери pack из `catalog/icons8-packs.json`.
4. Ищи icon по точному английскому semantic name.
5. Если точного icon нет — выбери ближайший понятный символ, но не меняй смысл действия.
6. Проверь размер и контраст.
7. Проверь accessibility.
8. Проверь attribution/license.
9. Только после этого меняй код.

## 12. Запрещённые анти-паттерны

- emoji вместо UI icon;
- unicode-символы вроде `⚙`, `✎`, `×` как случайная замена полноценному набору;
- 3+ разных icon styles на одном экране;
- иконки разной оптической массы в одной toolbar;
- растягивание SVG по одной оси;
- использование decorative icon как единственного способа передать важную информацию;
- скачивание всего Icons8 каталога или автоматический scraping;
- коммит API tokens, лицензированных исходников или сторонних asset packs без права распространения.
